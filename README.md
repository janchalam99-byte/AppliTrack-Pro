# ระบบจัดการรับ-ส่งของ ฝากของ และยืมของ ระหว่าง 2 สถานที่ (Two-Location Item Transfer & Loan Tracking Web App)

เว็บแอปพลิเคชันภาษาไทยแบบ **Mobile-first PWA** สำหรับจัดการการรับ-ส่งของ การฝากของไปกับรถ การยืมของ การคืนของ การถ่ายรูปหลักฐาน และการติดตามสถานะร่วมกันระหว่างผู้ใช้ 2 คน ข้อมูลซิงก์แบบ Real-time ผ่าน Supabase PostgreSQL

---

## 🚀 ฟังก์ชันหลักของระบบ

### 1. ระบบฝาก-ส่งของ (Transfer) & ยืม-คืนของ (Loan)
- **สร้างรายการ:** เลขที่รายการอัตโนมัติ (`TR-YYYYMMDD-xxx` หรือ `LN-YYYYMMDD-xxx`), ระบุสิ่งของได้หลายรายการในคำขอเดียว พร้อมจำนวนและหน่วยนับ
- **กำหนดสถานที่:** รองรับสถานที่ประจำ 2 แห่ง (แก้ไขชื่อได้ในหน้าตั้งค่า เช่น "สถานที่ A" และ "สถานที่ B")
- **ติดตามการยืม:** แสดงรายการที่กำลังยืมอยู่, คำนวณวันคงเหลือก่อนถึงกำหนด, ไฮไลต์สีแดงเมื่อ **เกินกำหนดคืน** อัตโนมัติ

### 2. ขั้นตอนการฝากของไปกับรถ (Workflow)
1. **ผู้ขอสร้างรายการ** &rarr; สถานะ `รอยืนยันคำขอ`
2. **อีกฝ่ายยืนยันคำขอ** &rarr; สถานะ `กำลังเตรียมของ`
3. **เตรียมของเสร็จ** (แนบรูปสภาพของ) &rarr; สถานะ `พร้อมฝาก`
4. **กดปุ่ม "ฝากของไปกับรถแล้ว"** &rarr; ระบบบันทึกเวลาที่ฝาก ผู้กด และรูปตอนฝาก &rarr; สถานะ `ฝากแล้ว รอผู้รับยืนยัน`
5. **ผู้รับตรวจสอบของจริง ถ่ายรูป และยืนยันรับ** &rarr; รองรับการรับครบ หรือ **รับบางส่วน / แจ้งปัญหา** (ของขาด, ของผิด, เสียหาย) &rarr; สถานะ `รับครบแล้ว` หรือ `รับบางส่วน` / `พบปัญหา`

### 3. ระบบถ่ายรูปหลักฐาน (Photo Evidence)
- ถ่ายรูปตรงจากกล้องมือถือ หรือเลือกจากคลังภาพ
- บีบอัดรูปภาพอัตโนมัติก่อนอัปโหลดเพื่อประหยัดแบนด์วิดท์
- จัดเก็บลง Supabase Storage แยกโฟลเดอร์ตามคำขอและขั้นตอน (`item_creation`, `pre_deposit`, `deposit`, `receipt`, `receipt_problem`, `pre_return`, `return_receipt`)
- แตะเพื่อเปิด Lightbox ดูรูปขนาดใหญ่
- รูปหลักฐานล็อกสิทธิ์ความปลอดภัย ห้ามผู้ใช้ทั่วไปลบทำลายหลักฐาน

### 4. ระบบการแจ้งเตือนและประวัติ (Timeline & Notifications)
- กระดิ่งแจ้งเตือนพร้อมตัวเลขนับจำนวนที่ยังไม่ได้อ่าน
- บันทึกประวัติสถานะ (Status History Timeline) ทุกขั้นตอนว่าใครเป็นผู้ดำเนินการ เมื่อใด พร้อมหมายเหตุ

### 5. รองรับ PWA (Progressive Web App)
- ติดตั้งเป็นแอปบนหน้าจอมือถือได้ (Add to Home Screen) ทั้ง iOS Safari และ Android Chrome

### 6. ระบบสำรองและกู้คืนข้อมูล (Backup & Restore System)
- สำรองฐานข้อมูล PostgreSQL ทั้ง 9 ตาราง (เป็น `.sql` และ `.json`)
- สำรองรูปภาพจาก Supabase Storage แยกต่างหาก พร้อมโครงสร้างเดิมและ SHA-256 Checksum
- รองรับการตั้งเวลาอัตโนมัติผ่าน Windows Task Scheduler
- ตรวจสอบความถูกต้องก่อนยืนยันความสำเร็จ และเก็บย้อนหลังตามจำนวนวันที่กำหนด
- อ่านคู่มืออย่างละเอียดได้ที่ [docs/BACKUP_AND_RESTORE_GUIDE.md](file:///c:/Users/Toto/Desktop/รับ-ส่งของ/docs/BACKUP_AND_RESTORE_GUIDE.md)

## 🛠️ เทคโนโลยีที่ใช้

- **Frontend:** React 19, TypeScript, Vite
- **Styling:** Tailwind CSS v4, Lucide React Icons
- **State & Data Fetching:** TanStack Query (React Query) v5, Zustand
- **Form & Validation:** React Hook Form, Zod
- **Backend & Database:** Supabase PostgreSQL with Row Level Security (RLS)
- **Authentication:** Supabase Auth
- **Storage:** Supabase Storage (Bucket: `item-photos`)

## 📋 วิธีตั้งค่าและเริ่มต้นใช้งาน

### ขั้นตอนที่ 1: ติดตั้ง Dependencies
```bash
npm install
```

### ขั้นตอนที่ 2: ตั้งค่า Supabase Database & Storage
1. เข้าไปที่ [supabase.com](https://supabase.com) แล้วสร้างโปรเจกต์ใหม่ (ฟรี)
2. ไปที่เมนู **SQL Editor** ในแดชบอร์ด Supabase
3. เปิดไฟล์ `supabase/schema.sql` ในโปรเจกต์นี้ คัดลอกโค้ดทั้งหมดไปวางใน SQL Editor แล้วกด **Run**
   - คำสั่งนี้จะสร้างตารางทั้งหมด 9 ตาราง (`profiles`, `locations`, `transfer_requests`, `transfer_request_items`, `item_photos`, `receipt_confirmations`, `receipt_confirmation_items`, `status_history`, `notifications`)
   - เปิดใช้งาน Row Level Security (RLS) พร้อม Policies
   - สร้าง Trigger สำหรับสร้าง Profile อัตโนมัติและสร้างเลขที่รายการ
   - สร้าง Storage Bucket ชื่อ `item-photos`

### ขั้นตอนที่ 3: สร้างบัญชีผู้ใช้ 2 คน
1. ไปที่เมนู **Authentication > Users** ใน Supabase Dashboard
2. กด **Add user > Create user** สร้าง 2 บัญชี เช่น:
   - บัญชีที่ 1: `user_a@domain.com` (สำหรับสถานที่ A)
   - บัญชีที่ 2: `user_b@domain.com` (สำหรับสถานที่ B)
3. รหัสผ่านตามที่ท่านกำหนด (อย่างน้อย 6 ตัวอักษร)
4. สามารถกำหนดชื่อเต็มและสถานที่ประจำของผู้ใช้ได้ในตาราง `profiles` หรือในหน้าตั้งค่าของแอป

### ขั้นตอนที่ 4: ตั้งค่า Environment Variables (`.env`)
คัดลอกไฟล์ `.env.example` เป็น `.env`:
```bash
cp .env.example .env
```
จากนั้นเปิดไฟล์ `.env` แล้วระบุข้อมูลจาก Supabase Dashboard (**Project Settings > API**):
```env
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### ขั้นตอนที่ 5: เริ่มต้นระบบ
```bash
npm run dev
```
เปิดเบราว์เซอร์ไปที่: `http://localhost:5173`

## 📱 โครงสร้างหน้าจอ

| เส้นทาง (Route) | หน้าจอ | รายละเอียด |
|---|---|---|
| `/login` | เข้าสู่ระบบ | หน้าล็อกอินด้วยอีเมลและรหัสผ่าน พร้อมคำแนะนำการตั้งค่า |
| `/` | Dashboard | สรุปยอดตามสถานะ, สรุปรายการยืมที่เกินกำหนด, รายการล่าสุด |
| `/requests` | รายการทั้งหมด | ตัวกรองสถานะ, ค้นหาตามชื่อสิ่งของ/เลขที่, รายการรอรับ |
| `/requests/new` | สร้างรายการใหม่ | ฟอร์มสร้างคำขอ เพิ่มได้หลายไอเทม, แนบรูปจริง |
| `/requests/:id` | รายละเอียดรายการ | ไทม์ไลน์สถานะ, คลังรูปหลักฐาน, ปุ่มดำเนินการ (ฝาก/รับ/แจ้งปัญหา/คืน) |
| `/loans` | ยืม-คืนของ | รายการที่กำลังยืมอยู่, คำนวณวันคงเหลือ, รายการเกินกำหนด |
| `/history` | ประวัติย้อนหลัง | คลังประวัติรายการที่เสร็จสิ้น/ยกเลิก ค้นหาย้อนหลังได้ |
| `/notifications` | การแจ้งเตือน | รายการแจ้งเตือนของฉัน, กดอ่านทั้งหมด |
| `/settings` | ตั้งค่า | ข้อมูลบัญชีผู้ใช้, แก้ไขชื่อสถานที่ A/B, ออกจากระบบ |

## 🔒 ความปลอดภัย (Security & RLS)
- ข้อมูลและรูปภาพทั้งหมดอยู่ภายใต้ **Row Level Security (RLS)**
- เฉพาะผู้ใช้ที่ล็อกอินเท่านั้นจึงจะสามารถเข้าถึงและแก้ไขข้อมูลได้
- รูปหลักฐาน (`is_evidence = true`) ป้องกันการลบทำลายโดยผู้ใช้ทั่วไป
- การอัปเดตสถานะและจำนวนถูกตรวจสอบความถูกต้องทั้งฝั่ง UI และ Database Constraints (เช่น จำนวนรับห้ามเกินจำนวนส่ง)
